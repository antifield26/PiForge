## P0 — 地基（出口：可登录、可下发编码任务、可观测、白名单生效、备份可恢复）

**目标**：打通安全入口、OpenCode 适配器、控制台只读监控、白名单 systemd、备份与恢复演练。

**依赖顺序**：
```
P0.1 项目骨架与文档固化
  → P0.2 SQLite wb.db + 认证
  → P0.3 部署 OpenCode serve（localhost）+ 适配器契约测试
  → P0.4 Agent 会话下发 + SSE 流式进度
  → P0.5 控制台只读监控（温度/负载/内存/SD 写入）
  → P0.6 systemd 白名单 + 审计
  → P0.7 备份脚本 + NAS/本地 + 校验 + 恢复演练
  → P0.8 Cloudflare 入口接线 + 密码登录联调
  → P0.9 写入减负核验（WAL/批量/重启 journald）
```

| ID | 标题 | 出口标准（含实机） | 预估 | 风险 |
|---|---|---|---|---|
| P0.1 | 骨架与配置 | monorepo 可 `npm run build`；systemd unit 草稿；文档链齐全 | 0.5d | 低 |
| P0.2 | 认证与 wb.db | 登录/登出/会话 TTL；WAL 生效；密码哈希正确 | 1d | 中（哈希/会话） |
| P0.3 | OpenCode 部署+适配器 | `opencode serve` 绑 127.0.0.1；`/api/info` 通；契约测试通过；RSS 记入 RESEARCH | 1d | 中（二进制/SSE） |
| P0.4 | Agent 任务流式 | 外网登录后下发真实编码任务，时间线见流式输出；权限 ask 可回复 | 1.5d | 高（事件映射） |
| P0.5 | 控制台只读 | 实时温度/负载/内存/SD 写入；图表 5min 聚合落盘 | 1d | 低 |
| P0.6 | 白名单+审计 | 白名单外启停返回 403 并审计；白名单内可控 | 1d | 中（权限） |
| P0.7 | 备份+恢复演练 | 备份成功+校验；从备份恢复 wb.db 一次成功 | 1d | 高（NAS） |
| P0.8 | 公网入口 | 外网经 CF + 密码进入工作台；OpenCode 不直接暴露 | 0.5d | 低 |
| P0.9 | 写入减负核验 | WAL+NORMAL；监控批量；重启后 journald 不落盘；写入日增量报告 | 0.5d | 中 |

**P0 综合出口（最终验收基线）**：
1. 外网设备经密码登录工作台；
2. 向 OpenCode Agent 下发真实编码任务并看到流式进度；
3. 控制台实时显示温度/负载/SD 写入统计；
4. 白名单外服务启停被拒；
5. NAS（或本地）备份成功且完成一次恢复演练。

**P0 合计预估**：约 8 人日。

## P3 — 告警闭环与控制面收口

**目标**：出事会叫你（告警），控制面可治理（会话/审计），升级与发布可重复（Playbook/门禁）。
**范围约定**：`antifield` NOPASSWD 收敛已并入 **FIX-4**（运维双账号 `piforge`，见 TASK-INDEX）；只读 PTY（P2.4）维持 `abandoned`。

**依赖顺序**：
```
P3.1 告警采集与投递
  → P3.2 阈值配置与通知面板
P3.3 会话管理
  → P3.4 审计检索 UI
P3.5 OpenCode 升级 Playbook
  → P3.6 发布纪律
  → P3.7 备份状态面板（联动 P3.1）
```

| ID | 标题 | 出口标准（含实机） | 预估 | 风险 |
|---|---|---|---|---|
| P3.1 | 告警采集与投递 | 备份失败/服务掉线/SD 超阈值/内存不足生成通知；工作台可见；可选 webhook；去重冷却 | 1.25d | 中 |

## P4 — 运行时可解释与发布加固

**目标**：让长期无人值守仍可解释写入、可恢复公网入口、发布门禁含供应链；运维权限收敛不在本章（已并入 **FIX-4**）。
**范围约定**：不含运维双账号/`antifield` 收敛（FIX-4.9）；不含内核 `cgroup_disable=memory` 根治（仅检测告警）；只读 PTY 维持 `abandoned`。

**依赖顺序**：
```
FIX-4 审计收尾（含运维双账号）完成
  → P4.1 PiForge 写入归因
  → P4.2 归因阈值告警（可选）
  → P4.3 cgroup/限制生效检测
P4.4 公网入口恢复手册（可并行）
  → P4.5 安全头抽查并入红线
P4.6 前端冒烟 + P4.7 备份告警闭环再演
  → P4.A 综合出口
```

| ID | 标题 | 出口标准（含实机） | 预估 | 风险 |
|---|---|---|---|---|
| P4.1 | PiForge 写入归因 | 按 gateway/backup/opencode 估算字节进 sd_health 或 metrics；UI/PERF 能区分「工作台 vs 设备其它」 | 1d | 中 |
| P4.2 | 归因阈值告警（可选） | 阈值 API 可扩；实机一条真实告警 | 0.5d | 低 |
| P4.3 | 资源限制生效检测 | MemoryMax 等未生效时 alerts/info 可见；文档记载平台限制 | 0.25d | 低 |
| P4.4 | 公网入口恢复手册 | 530/1033 检查→恢复→e2e 可照抄；入口恢复后补 HSTS | 0.5d | 低 |
| P4.5 | 安全头红线抽查 | HSTS/CSP 探测纳入 release-check 红线 | 0.25d | 低 |
| P4.6 | 前端轻量冒烟 | 登录→面板→登出可自动断言（可选层） | 0.5d | 低 |
| P4.7 | 备份失败闭环再演 | 模拟失败→告警→面板状态可读 | 0.25d | 低 |

**P4 合计预估**：约 3.25 人日（不含 FIX-4）。

**P4 综合出口**：
1. 写入归因可在控制台/PERF 解释；
2. 公网入口有恢复手册，恢复后 e2e 可过；
3. 发布门禁含依赖审计与安全头探测；
4. 限制未生效/备份失败能进告警；
5. `npm run verify` + 实机 e2e/fixes 全绿；红线无回归。
